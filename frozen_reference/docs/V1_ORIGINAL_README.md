# 负资金费率"现货 + 永续"策略：可复现版

> 研究/回测代码，不是投资建议。数字都是历史模拟，不是实盘业绩。仓库不含密钥、持仓或库存数据。没有 LICENSE 文件（许可证未决定，默认保留所有权利）。
> 报告、图表和 PDF 不放在这里，内部另发。

## 1. 策略规则（头条口径）
- **本金**：1000 万 USDT（10M）。
- **做什么**：某币永续资金费率为负时，卖出自有现货（库存口径 A，只用已有库存借出的币），同时做多等量永续合约，收取空头付给多头的资金费。借币利息按假设为 0。
- **进场**：资金费率为负、期望收入（资金费 + 基差收敛）不低于预期进场成本的 2 倍时进场（`r7_lib.py` 的 `gate_r7`：`ei >= m * C`，`v13lib.run_fix` 默认 `m=2.0`）（`run_r7.py` 的 r7 闸门，冲击成本用过去数据校准）。
- **出场（0h）**：持仓期间最近 24 小时已结算的资金费（含自身冲击）累计转为净支付时，当小时立即出场，不等确认（配置 `cons_c0`，出场信号 X5）。
- **仓位上限**：每币不超过执行团队给的上限（USDT 上限和币数量上限都要满足）；不超过该币未平仓量（OI）的 10%；每小时成交不超过该小时成交量的 3%（pov）。
- **成本模型（cons 保守口径）**：手续费按币安 VIP3（见第 3 节）；买卖价差和冲击成本按公开盘口/成交数据逐币逐小时校准；自身冲击 `k_imp=4`：我们每占某币 1% OI，资金费率被抬高 4 bp/8h（从未用实盘标定）；资金费按全额计入，包括自身冲击；残余成本放大 3 倍。
- **窗口**：样本内 IS 到 2026-06-30，留出期 HO 是 2026-07-01 到 2026-10-27，全年 FY 是 2025-10-28 到 2026-10-27。

## 4. 三种执行方式
1. **全 taker（默认，主线）**：两条腿同时吃单，成交价 = 小时 VWAP + 校准过的价差和冲击成本。
2. **永续 maker + 现货 taker**（`--exec perp_maker`）：永续挂限价单；成交多少，就在同一小时用吃单在现货对冲多少。
3. **现货 maker + 永续 taker**（`--exec spot_maker`）：反过来。

挂单模型（偏乐观，因为只有 1 小时 K 线）：
- **限价和成交条件**：限价 = 本小时开盘价；本小时价格**穿过**限价 0.2% 才算可能成交。
- **排队折扣**：实际成交量 = 可成交量 × `--fill`（0.25 / 0.5 / 0.75 / 1）。`--fill` 是**尝试成交率**，不是 maker 占比：只要部分成交，该币就被锁定，下一小时剩余部分强制走吃单（`engine_v12s.py` 约 L514–518、L710–714）。所以 fill 从 75% 到 100% 时 maker 名义本金会跳升（见下表 maker 名义占比列）。
- **逆向选择**：每笔挂单成交多付 `--adv` ×（小时最高 − 最低）/2，`--adv` ∈ {0, 0.5, 1}。
- **对冲**：另一腿同一小时按吃单模型价成交。`--hedge worst`（按小时最差价对冲）只用作压力测试。
- **没成交的部分**：下一小时两条腿一起改用吃单。这一小时少收的资金费照实计入；价格变动已被对冲，不另记成本（`--gap on` 是旧的单边口径，只用作压力测试）。

**怎么理解结果**：maker 的数字只是**上限**，真实结果取决于实盘测出来的逆向选择，仓库数据估计不了。主线仍是全 taker。

FY 年化随 adv 线性下降，所以可以解出盈亏平衡 adv。比较时用两个基准：
- **52.76**：全 taker 主线。
- **53.61**：fill=0 基线（同等节流），即 fill 0，下一小时两腿一起吃单。

## 5. 资金费深度分档（只用入场那一小时已知的信息）
按入场那一小时引擎已知的 8h 等效预期费率 r8 分档。不用之后才知道的信息，比如这一段最深的费率或持仓时长。
- T1：r8 > −0.1%
- T2：−0.1% ~ −0.5%
- T3：−0.5% ~ −1%
- T4：≤ −1%

v1 主线在四档里的入场和出场规则完全相同（见第 1 节），档位只用来分账。`--json` 会输出每档的笔数、净利和平均持有小时。

`--entry-tiers`（只允许在某些档位入场）是**待前瞻验证**的对比变体：这些候选是看过分档结果后才定的，不作头条，也不替换主线。

注：档位是事后挑选的；各档结果的路径不能叠加。例如只开 T4 有 457 笔，而主线里 T4 只有 216 笔（仓位和资金占用互相影响）。

## 7. 代码结构
- `repro/run_headline.py`：唯一入口。
- `repro/lib/`：引擎和规则模块（`engine_v12s.py` 是带逐笔记账的引擎，`lib12s.py` 负责加载数据和仓位上限，`r9_run.py`/`r10_run.py` 定义口径 `cons_c0`，`run_r7.py`/`r7_lib.py` 负责成本校准和进场闸门，`v13lib.py` 是运行封装）。
- `repro/calib/calib_dl.py`：从币安公开 bookDepth / aggTrades 生成冲击校准表（独立脚本，复现头条不需要运行）。
