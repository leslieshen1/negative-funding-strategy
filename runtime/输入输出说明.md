# JSON v2.1 输入、输出和回执

## 通用约定

UTF-8 JSON。价格、数量、金额、费率用普通十进制字符串，不用浮点数、科学计数法或百分数字符串。`"-0.001"` 为 −0.1%。缺失用 null 并标记数据不完整，不能用零冒充。时间为 UTC Unix 毫秒整数；经济事件时间与实际接收时间分开，禁止未来输入和重复 JSON 键。

三种消息均绑定 `strategy_id`、`profile_sha256`、`engine_source_sha256`。配置哈希使用 MODEL_PROFILE 声明的规范 JSON 编码。旧 ID、旧哈希不能通过新 schema。

## 1. 策略输入

执行方提供真实状态，不需要预测费率持续期、预计收益或成交冲击。

| 对象 | 必要信息／含义 |
|---|---|
| 消息头 | 请求ID、决策时间、账本版本、模式和模型标识 |
| `portfolio` | 固定本金、联合策略损益、已用投入、工作订单预留、A可用USDT、B钱包／权益／1x保证金／实际持仓名义金额／可用及可划转额、未到账划转总额、快照接收时间、全局风险状态 |
| `instrument` | 唯一原币、现货／永续符号、合约乘数、两腿步长、两腿最低数量及最低金额 |
| `position` | 实际已卖未回购现货、实际永续交易所数量与原币数量、已有退出锁、本轮ID、已用投入、未成交新增量及投入预留、本轮待归还义务 |
| `market` | 当前双腿买卖报价及接收时刻、上一已完成小时价格、已知OI、前24h双腿较小成交额、前一完整小时双腿成交额、该小时已成交与预留预算、已结算费率明细及历史完整性 |
| `limits` | 实际收到的原币总上限与扣除已有订单预留后的可新增原币量 |
| `risk` | 暂停新增、强制退出、对应已收到公告／召回时间与原因 |

`market.settlements` 保留原始费率、该次间隔、结算与接收时间，包含零费率。24h窗口为 `(as_of−24h,as_of]`。以最大结算经济时间确定最新值，不以最后收到的一条旧记录回滚最新费率。

容量窗口必须为当前决策前刚完成的一小时，不用当前未完成小时成交量，也不把真实接收时间回填到经济时间。`capacity_view` 固定 `causal_online`；深度仍必须标明 observed／volume_proxy／unavailable，代理不等同盘口实测。

兼容字段 `limits.per_coin_cap_usdt`、`max_position_notional_from_oi_usdt`、`max_position_notional_from_volume_usdt` 与 `market.shared_slice_budget_remaining_usdt` 可省略，由策略适配器从原始数据和冻结配置计算；若传入则必须一致，不能沿用旧10%限制。

A/B可用资金必须已经扣除现有订单冻结、保证金和划转预留。`unsettled_transfer_usdt` 只用于记录，不能加入可用资金。所有正常输出逐项返回输入币种状态；输入范围之外的账户持仓仍必须计入组合投入、保证金及预留总额。

## 2. 策略输出

| 字段 | 语义 |
|---|---|
| `decision_id`、`input_request_id` | 唯一决策与对应请求，用于幂等 |
| `ledger_version` | 计算时实际账本版本；成交后旧版决策不能继续消费 |
| `valid_until_ms` | 最长60秒；接收时仍须检查报价和账户不超过10秒，不代表60秒内行情永远有效 |
| `desired_pair_qty_token` | 本轮最终目标，退出锁定时为零 |
| `target_pair_qty_token` | 本次许可量全部成交后的实际配对数量 |
| `delta_pair_qty_token` | 本次目标减当前数量；与两腿本次允许数量对应 |
| `target_perp_qty_exchange` | 本次目标原币数量除以合约乘数 |
| `max_slice_notional_usdt` | 本决策本币本次总允许成交预算；子订单合计不得超过，不是每个子订单都可重复使用的额度 |
| `exit_locked`、`risk_state` | 本轮锁退与风险状态；不能因报价缺失或下一条负费率取消 |
| `legs` | 本次允许的两腿方向、数量及价格界限；执行方负责界限内拆单、下单、撤单及补腿 |
| `model_diagnostics` | 策略方给出的r7预计收入、完整成本、样本完成时点与数量、有效费率、ADL代理、模型及校准标识 |
| `transfer_requests` | 划转意图；必须等实际到账并提交新账户快照后再释放相关成交许可 |

ENTER：空仓新增；ADD：已有对冲加仓；REDUCE：风险减仓；EXIT：本轮锁退、可分批；HOLD：本次不交易；RECONCILE：持仓／状态不一致，不发送普通配对订单。

正常新增两腿：A卖现货、B买永续。正常减少两腿：A买现货、B卖永续且 reduce_only=true。两腿都以同一原币量核对。方向敞口不一致时由执行方按 RECONCILE 目标及风控限制补腿；当前版本不给出虚构的补腿成交。

本次只允许退出1,000、当前10,000的例子见 `17_partial_exit`；缺买回现金而先申请B→A划转见 `19_transfer_wait`。未成交、拒单、部分成交之后均以实际回执和新状态计算，不能把原目标当成实际成交。

每腿 `limit_price_usdt_per_exchange_quantity` 对 BUY 是最高允许价，对 SELL 是最低允许价，单位为该腿交易所数量的 USDT 单价。1000系永续的该价格同样含1000倍单位，不能使用每原币价格冒充。示例采用当时合成买卖报价作为界限，不替实盘标定滑点。现金预留按 BUY 的最差允许价加费用计算，不按展示的较低卖一价计算。放宽价格界限必须重新计算完整成本、现金及成交预算，不得由执行侧擅自突破。

## 3. 执行回执

回执包含实际成交ID、订单ID、两腿成交数量／价格、真实手续费及资产、实际资金费、划转状态、实际仓位与敞口、原币恢复／归还阶段，以及处理前后账本版本。

资金费是实际现金增量，不能再叠加 k=4 估计影响。非USDT手续费原样记资产与数量；折算价格及可用时间另留账，不能无依据折算为零。

`PENDING` 不是 `SETTLED`；`RESTORED_IN_A` 不是 `RETURNED_TO_PROVIDER`。执行回执按真实已发生事件记账，即使原决策已过期也不能丢失实际成交。实际迟到事件需更新账本和风险，不得回填成更早已知的信息。

## 4. 校验器边界

离线校验器检查结构、配置、时点、数量、两腿方向、样本时点、阈值、共享预算、资金及锁退等约束。它只验证报文声明之间的一致性，不能证明上游市场／余额真实、完整，不能生成r7预测，也没有生产持久化对账功能。

跨请求重复、跨进程额度竞争、交易所真实回执及强平等场景须按 `联调验收.md` 完成。一个报文通过校验不代表可以直接生产执行。

## RC2计算路径

策略标识为 `nfb.strategy.20261108.rc2`，协议2.1.0。`decision.py`已接上r7收入／成本及决策计算，`validate.py`继续只做合同检查。执行侧不需要填预计收入或成本。

每币可增加 `model_history`，提供26条连续小时的双腿收盘价、USDT计价OI、结束时间、接收时间和来源。缺少该窗口时停止新增，已有退出和减仓仍处理。真实输入使用observed来源，历史代理必须显式重放。

输出诊断增加模型有效起止时间、联合／边际回退来源、样本数和结局截止、波动率、成本系数、校准可用时点／年龄及模型快照哈希。未知估计的截止时间为null，不用1970年或零时间伪装已知。收入样本截止必须早于实际刷新节点；保留2025年10月28日这一历史初始锚点，之后使用月初。

模型快照哈希固定在机器配置中，不能只改权重文件。运行样例请使用 `runtime_examples/`；旧 `examples/` 是合同形状样例，不能把其中手填的模型诊断当成真实算法输出。
